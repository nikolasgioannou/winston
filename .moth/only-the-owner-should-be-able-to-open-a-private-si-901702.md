Sites are private by default: only their signed-in owner can open them (parent's spec, Access).

**What to build**
- Visiting a private site without access redirects to `runwinston.com`, which (after sign-in if needed) checks the visitor owns the site and redirects back with a short-lived, single-use signed ticket. The dispatch Worker verifies it (a public key it holds, so no call back to us per request), then sets its own signed, host-only, HttpOnly cookie for that site and serves it.
- Someone who isn't the owner sees a plain "this site is private" page.
- Ticket and cookie formats documented in the Sites section of docs/design.md, and §13 updated.

**Done when**
- [x] The owner opens a private site after signing in, and stays in on later visits
- [x] A signed-out visitor and a different signed-in user are both refused
- [x] A replayed, expired or other-site ticket is refused (tests)

## As built

- **Passes, not tickets.** `web` signs a pass `{ sub, site, nonce, exp }` with an Ed25519 seed (`SITES_PASS_KEY`, generated by `setup.sh`), and the dispatch Worker verifies it with the public key. The pass itself goes in the site's cookie (30 days), so the dispatch Worker holds no secret and keeps no state.
- **Single use became nonce-bound.** True single use would need state at the edge (KV is eventually consistent). Instead the site sets a nonce cookie before sending the browser to sign in, and only accepts a pass carrying it. A replayed pass works only in the browser it was issued to, which is the owner anyway.
- `web` doesn't check ownership (there's no sites table yet); the dispatch Worker compares the pass's user with the route's `ownerId`. A non-owner gets the private page, with no sign-in loop.
- Checked by tests through Miniflare's real workerd (Ed25519 verification included), the handler tests and `sitePassRedirect`'s tests. The Google sign-in leg wasn't run in a browser, because another checkout's stack holds the ports; it's the existing `returnPath` flow.
